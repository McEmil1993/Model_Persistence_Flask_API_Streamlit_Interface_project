# Student Pass Prediction System

A classroom demonstration project combining three lesson exercises into one integrated application:

1. **Model persistence:** `train_model.py` trains a model and saves it as `student_pass_model.joblib`.
2. **Flask API:** `app.py` loads that saved model once at startup and exposes `POST /predict`.
3. **Streamlit interface:** `streamlit_app.py` sends user input to the Flask API and displays its response.

The training labels are based on a deliberately invented rule and synthetic data. Predictions are for learning and demonstration only, not real academic assessment.

## Requirements

- Python 3.10 or newer recommended
- Internet access for the initial package installation
- Windows Command Prompt or PowerShell

## Setup on Windows

Open Command Prompt or PowerShell and change to the project folder. For example:

```powershell
cd path\to\student_pass_prediction
```

Create and activate a virtual environment:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, use Command Prompt instead:

```bat
.venv\Scripts\activate.bat
```

Install the packages:

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Run the project

### 1. Train and save the model

Run this once before starting the API:

```powershell
python train_model.py
```

The script creates `student_pass_model.joblib` and prints three example predictions. Re-run this script only when you want to retrain or replace the demonstration model.

### 2. Start the Flask API

Open **Terminal 1** in the project folder, activate the virtual environment if needed, and run:

```powershell
python app.py
```

The API should be available at `http://127.0.0.1:5000`. Keep this terminal open.

Check the API status in a browser at `http://127.0.0.1:5000/`.

### 3. Test the API with curl

Open **Terminal 2** in the same project folder. In Windows PowerShell, use `curl.exe` so the real curl program is called:

```powershell
curl.exe -X POST http://127.0.0.1:5000/predict -H "Content-Type: application/json" -d "{\"student_name\":\"Juan Dela Cruz\",\"study_hours\":5,\"attendance_percentage\":90}"
```

The prediction depends on the trained model; do not assume it will always be `Pass`.

Try invalid attendance to check validation:

```powershell
curl.exe -X POST http://127.0.0.1:5000/predict -H "Content-Type: application/json" -d "{\"student_name\":\"Juan Dela Cruz\",\"study_hours\":5,\"attendance_percentage\":120}"
```

This should return HTTP 400 with an error message.

### 4. Start the Streamlit interface

Open **Terminal 3** in the project folder and run:

```powershell
python -m streamlit run streamlit_app.py
```

Streamlit will show a local URL, usually `http://localhost:8501`. Open it in your browser, enter the student information, and click **Predict Result**.

Keep both the Flask and Streamlit terminals running while using the interface.

`student_pass_model.joblib` is generated locally. It will not exist until `train_model.py` has run successfully.

## How the integrated workflow works

```text
train_model.py
      |
      v
student_pass_model.joblib
      |
      v
Flask API (app.py) <------ JSON request ------ Streamlit (streamlit_app.py)
      |                                         ^
      |---------- JSON prediction response -----|
```

Flask loads the model when the API process starts. Each prediction request reuses that in-memory model; it does not retrain the model.

## Testing checklist

- [ ] `python train_model.py` finishes and creates `student_pass_model.joblib`.
- [ ] The training script prints three predictions for different inputs.
- [ ] `python app.py` starts without a missing-model error.
- [ ] `GET http://127.0.0.1:5000/` reports that the API is running.
- [ ] A valid `POST /predict` request returns student details and a prediction.
- [ ] Attendance below 0 or above 100 returns HTTP 400.
- [ ] Negative study hours or study hours above 24 returns HTTP 400.
- [ ] Missing fields or invalid JSON return an error response.
- [ ] The Streamlit interface displays a prediction returned by Flask.
- [ ] With Flask stopped, Streamlit displays a connection error rather than crashing.
- [ ] Multiple predictions work without retraining the model.

## How this satisfies the three exercises

- **Exercise 1 — Model Persistence:** `train_model.py` uses `joblib.dump()` to save the trained classifier. `app.py` uses `joblib.load()` to load it.
- **Exercise 2 — Flask API:** `app.py` accepts JSON at `POST /predict`, validates values, and returns a JSON response.
- **Exercise 3 — Streamlit Interface:** `streamlit_app.py` provides student inputs, calls the API, and displays its prediction and explanation.

## Short presentation guide

> Good day, Sir/Ma'am. Our project is the Student Pass Prediction System. It combines model persistence, a Flask API, and a Streamlit interface into one application.
>
> First, `train_model.py` creates a demonstration dataset, trains a decision-tree classifier, and saves it using joblib. This demonstrates model persistence because the model can be loaded again without training for every prediction.
>
> Second, Flask acts as the API. It receives the student's study hours and attendance percentage, validates the input, uses the saved model, and returns the result as JSON.
>
> Third, Streamlit is the user interface. It sends the student's details to Flask and displays the returned prediction. This shows how the three exercises work together.
>
> The dataset is synthetic and the model is for educational demonstration only. It should not be used to make real academic decisions. Thank you.

## Notes

- This project is intended for local classroom use. The API binds to `127.0.0.1`, so it is not exposed to other computers on the network.
- The example data and rules are invented for teaching. They do not establish a reliable relationship between attendance, study time, and actual academic outcomes.
- Anyone who receives a serialized model file should only load it from a trusted source.
